# ОРТОС

Премиальный планировщик **ортогнатической хирургии** — отдельное настольное
приложение (Windows **.exe**, Electron), светлый анимированный интерфейс.
Clean-room аналог ортогнатического планирования Dolphin Imaging (собран по
методу пака replica — повторяет функции и поток, без кода/бренда/контента
оригинала; нормы — общедоступные). **Это отдельная программа, не OSSA.**

## Поток (7 шагов)

1. **Пациент** — ФИО, пол, дата; загрузка данных.
2. **МСКТ → ТРГ** — загружаете серию **МСКТ (DICOM)**, программа строит боковую
   **ТРГ** (проекция-DRR), масштаб берётся из DICOM автоматически. Можно
   загрузить и готовую плёнку ТРГ (фото).
3. **Точки** — для **каждой** цефалометрической точки показывается
   **схема-подсказка** (где её ставить) и описание; точку вы ставите **сами**
   кликом на ТРГ, затем правите перетаскиванием. 17 костных + 7 мягкотканных.
4. **Фото** — загрузка **фотографии профиля** пациента и **прогноз профиля
   «до → после»**: вы отмечаете на фото мягкотканные точки (G, Prn, Sn, Ls, Li,
   Pog′, Me′ — те же, что на ТРГ), программа привязывает фото к плану (МНК-подобие
   ТРГ↔фото) и переносит прогнозируемые перемещения мягких тканей на фото,
   деформируя его (кусочно-аффинно). Ползунок «исходное ↔ прогноз», экспорт PNG.
5. **Анализ** — цефалометрия с нормами: SNA, SNB, ANB (+ класс), Wits, SN-MP,
   FMA, U1-NA, L1-NB, межрезцовый, носогубный.
6. **План** — перемещения сегментов (Le Fort I, BSSO, гениопластика) ползунками.
   **Сегментация ТРГ**: линии остеотомий (Le Fort I / BSSO / гениопластика). По
   завершении планирования **перемещение происходит на самом снимке** —
   кусочно-аффинная деформация ТРГ по ориентирам (до → после), а не только линии.
   **Уточнённый прогноз мягких тканей** по средним H/V-коэффициентам «мягкое/костное».
   Наложение до/после, сводка и анализ «до → после», экспорт PNG.
   - **3D-реконструкция черепа по МСКТ (до → после)**: переключатель «ТРГ ↔
     3D-череп» в блоке «Контроль результата». Поверхность кости извлекается из
     объёма МСКТ (Surface Nets по порогу HU, сглаживание Тобина, отсев стола/
     подголовника и осколков). Подвижные сегменты (**в/ч**, **н/ч**, **подбородок**)
     выделяются по ориентирам и перемещаются жёстко по плану — той же математикой,
     что и профиль. Ползунок «до ↔ после» морфит реконструкцию, модель вращается
     мышью (зум — колесо). Сегментация по ориентирам — схематична; для точной
     нужна полноразмерная (не обрезанная) серия МСКТ.
7. **Шаблон** — **функциональный хирургический окклюзионный сплинт** по итогам
   планирования: центральные **ложа под зубы** (окклюзионный оттиск) +
   буккальные/язычные **ретенционные стенки** — сплинт **надевается на зубы** и
   удерживается, служит интраоперационным **ключом окклюзии**.
   - **Адаптация по STL-сканам (золотой стандарт)**: кнопки «загрузить STL»
     верхнего и нижнего зубных рядов. Если загружены оба внутриротовых скана, ложа
     и ретенционные стенки строятся по **реальным** окклюзионным поверхностям
     пациента — вершины мешей подаются как облако точек в то же ядро, что и КТ
     (`waferFromCloud`): аппроксимация дуги, проверка физиологичности, сегментация
     боковых поверхностей коронок, стенки → водонепроницаемый манифолд-STL. Оба
     скана — в одном положении смыкания. **Автоориентация**: программа сама находит
     окклюзионную плоскость (PCA) и ставит сканы правильно, поэтому ось/разворот из
     сканера значения не имеют — грузите как есть. Точнее сегментации КТ. Приоритет
     режимов: **STL > МСКТ > параметрический**.
   - **Адаптация по МСКТ**: если загружена дентальная КТ достаточного разрешения
     (CBCT, воксель ≤0.4 мм), дуга, ложа **и стенки** строятся по данным пациента —
     сегментация эмали/кости по плотности (HU), определение окклюзионной
     плоскости, аппроксимация зубной дуги, выборка окклюзионных поверхностей в/ч и
     н/ч → негативный оттиск. **Сегментация боковых поверхностей коронок**: по
     каждой станции дуги определяются буккальная/язычная границы и высота коронок —
     ретенционные стенки повторяют ширину и высоту зубов (надеваются и удерживают).
     Нижняя дуга смещается на межчелюстной сагиттальный шаг из плана.
   - **Проверка физиологичности дуги** (ширина/глубина/покрытие): если КТ грубая
     (напр. обзорная 2 мм) или обрезана — честный **откат на параметрическую дугу**
     с указанием причины в интерфейсе.
   - **Два типа (разная логика)**:
     - *Финальный* — обе челюсти в итоговом положении (AP-шаг = mdAdv−mxAdv,
       вертикаль ~0): ключ финальной окклюзии.
     - *Промежуточный* — **в/ч перемещена, н/ч исходная** (BSSO ещё не выполнен):
       фиксируется только выдвижение в/ч (AP-шаг = −mxAdv), а импакция в/ч
       открывает/закрывает прикус против неподвижной н/ч (шаблон получается
       клиновидным/толще). Ставится интраоперационно для позиционирования в/ч
       после Le Fort I.
   - Экспорт **STL** (водонепроницаемый манифолд, готов к 3D-печати) + вращаемый
     3D-предпросмотр. Сохранение/открытие `.orthos`.

> Для адаптации по зубам нужна дентальная КТ/CBCT (≤0.4 мм, FOV = челюсти). На
> обзорной КТ дуга параметрическая — подгоняется под гипсовую/цифровую модель; из
> плана берётся межчелюстное соотношение. Инструмент планирования, не мед. изделие
> — проверяйте клинически.

## Сборка .exe

CI (`.github/workflows/build-orthos.yml`) собирает Windows-установщик:
Actions → запуск **Build ORTHOS (Windows)** → **Artifacts** → `ORTHOS-Windows-Installer`.
Локально: `npm install && npm run dist` (в папке `orthos/`).

## Технологии

Electron + ванильный JS (без сборщика): `index.html` + `styles.css` + `app.js`
+ `skull.js` (схемы-подсказки). Разбор несжатого DICOM — в приложении.
Сжатый DICOM (JPEG/JPEG2000) — выгрузите несжатую серию.

> Инструмент планирования, не диагностическое мед. изделие. Нормы и прогноз
> мягких тканей ориентировочные — проверяйте клинически.
