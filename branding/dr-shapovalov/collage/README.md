# Коллажи «до / после» — фирменный стиль @dr__shapovalov

Шаблон, утверждённый на первом кейсе (краниофациальная микросомия, дистракция
нижней челюсти). Все будущие коллажи для Instagram и Telegram делаются по нему.

> **Фото пациентов в репозиторий не коммитятся никогда.** Работать в папке
> `cases/` (она в `.gitignore`) или во временной папке сессии.

## Дизайн

| Параметр | Значение |
|---|---|
| Формат | 1080×1440 (3:4, сетка профиля Instagram). Заголовок и подпись внутри центральной зоны 4:5, чтобы обрезка до 1080×1350 ничего не съела |
| Фон | `#F4F3F0` |
| Текст | `#16181A`, второстепенный `#8A8781` |
| Шрифт | Manrope (Google Fonts, SIL OFL): заголовок 800/36, подзаголовок 500/36, метки 800/17, ник 700/21 |
| Заголовок | по центру: **«Лицо»** или **«Прикус»** + серым « · до и после» |
| Фото | скругление 20 px, отступ между фото 14 px, поля 56 px |
| Метки | в левом верхнем углу каждого фото: «ДО» — белая плашка, «ПОСЛЕ» — тёмная |
| Подпись | внизу по центру: знак «Ш.» (`../mark-dark.svg`) + `@dr__shapovalov` |
| Глаза | закрыты сплошными чёрными кругами (радиус ≈ 0,6 ширины глаза). На профиле закрывается и дальний глаз, если он виден |

### Раскладки

- `pairs` — лицо: ряды «до | после» (анфас, правый профиль, левый профиль),
  все рамки одного размера. Для анфаса рамки почти квадратные (`max_width` ≈ высоте ряда),
  потому что вертикальные фото анфаса шире не влезают.
- `pair_then_stacked` — прикус: сверху фронтальная пара «до | после»,
  ниже боковые снимки на всю ширину, «до» над «после». Так мелкие фронтальные
  исходники уменьшаются, а не растягиваются.

## Масштаб и кадрирование

«До» и «после» приводятся к одному масштабу по размерам, которые лечение не меняет,
и ставятся так, чтобы опорная точка (глаз, центр зубной дуги) совпадала по положению:

| Снимок | `anchor` (опорная точка) | `ref` (эталонный размер) |
|---|---|---|
| Анфас | середина между зрачками | расстояние между зрачками |
| Профиль | центр видимого глаза | высота ушной раковины |
| Прикус фронтально | межрезцовая линия на уровне окклюзии | ширина центральных резцов (при расхождении с высотой коронки — среднее) |
| Прикус сбоку | центр зубной дуги | высота коронки центрального резца |

`include` — точки, которые обязаны остаться в кадре (подбородок, кончик носа, ухо,
крайние зубы). `fit.py` подбирает общий масштаб и положение рамки; фото только
обрезается и равномерно масштабируется, никогда не растягивается. Если исходник
позволяет только разные масштабы, скрипт печатает `scale mismatch`, а если фото
приходится увеличить больше чем в 1,3 раза — предупреждение.

Координаты мерятся в пикселях исходного фото (после поворота по EXIF): удобно
нарезать участок с сеткой и читать значения.

### Дополнительные поля кейса

| Поле | Где | Что делает |
|---|---|---|
| `enhance` | у фото: `"photo"` или `"ct"` | мягкая коррекция уровней, цвета и резкости; анатомию не меняет. Для КТ тон остаётся серым |
| `badge` | у фото: `{"value": "7,93 мм", "caption": "сагиттальная щель"}` | крупная плашка с измерением в правом нижнем углу |
| `precrop` | у фото: `[l, t, r, b]` | сначала обрезать рамку скриншота; замеры указываются по полному исходнику |
| `row_weights` | у слайда `pairs` | относительная высота рядов, например `[232, 460, 460]` |
| `independent_rows` | у слайда `pairs` | номера рядов, где «до» и «после» сняты слишком по-разному для общего масштаба (прикус крупным планом и обзорно, срезы КТ разного поля) — каждое фото кадрируется отдельно |

## Запуск

```bash
pip install pillow cairosvg
python3 render.py cases/<кейс>/case.json     # -> face.jpg, bite.jpg рядом с case.json
```

Пример файла кейса со всеми полями — `case.example.json`.
