Мой файл с кодом в порядке — на строке 18 стоят правильные прямые кавычки `"` (проверил байты). Значит, ошибка появилась уже у тебя в Apps Script, и почти наверняка причина одна:

## Когда вписывал свой TOKEN, кавычки превратились в «ёлочки» или «умные» кавычки

Строка 18 — это:
```javascript
const TOKEN = "ПОСТАВЬТЕ_СВОЙ_СЕКРЕТ";
```

Если ты заменил `ПОСТАВЬТЕ_СВОЙ_СЕКРЕТ` на свой пароль, то вместе с этим кавычки `"` могли автозаменой стать `«»` или `“”` — Apps Script их **не понимает** и подсвечивает строку 18 красным.

**Должно быть ровно так** (прямые кавычки, латиница/цифры без пробелов и без `"` внутри):
```javascript
const TOKEN = "kdo2026";
```

### Проверь:
1. Кавычки — только прямые `"` `"`, не `«мой»`, не `"мой"`.
2. Внутри пароля нет кавычек и точки с запятой.
3. В конце строки одна `;`.

Самый надёжный способ — **не печатать кавычки вручную**: оставь `"` из файла на месте, а заменяй только текст между ними (выдели `ПОСТАВЬТЕ_СВОЙ_СЕКРЕТ` двойным кликом и набери свой пароль — кавычки не трогай).

---

Если дело не в кавычках — **пришли точный текст красной ошибки** (там после «Строка 18» написано, что именно не так, например `SyntaxError: ...` или `Identifier 'TOKEN' has already been declared`). По этой фразе я скажу точную причину. Второй вариант, который иногда помогает, — заменить в строке 18 `const` на `var`:
```javascript
var TOKEN = "kdo2026";
```
Это убирает конфликт, если `TOKEN` уже где-то объявлен в проекте.

## Сначала про EAT-10
Ты прочитал «ЕОТ» — это **EAT-10** (Eating Assessment Tool-10), стандартный опросник-скрининг нарушения глотания. 10 вопросов, пациент каждый оценивает 0–4 балла (0 — нет проблемы, 4 — тяжело), сумма 0–40. **< 3 — норма, ≥ 3 — есть дисфагия.** Это проверенный инструмент (Belafsky, 2008), поэтому я и взял его как объективную цифру вместо «на глаз».

---

## Теперь про функциональный индекс — ты абсолютно прав

«1 балл за апноэ, 0.5 за храп» — это действительно субъективно, и «почему 1, а не 0.9» ответа не имеет. Раз мы уже привязали к каждому нарушению **объективную цифру**, можно сделать индекс, где **каждое число объяснимо**. Вот что я предлагаю (двухслойная схема):

### Слой 1. Насколько нарушение выражено — считаем из самой цифры
Для каждого метода берём две опорные точки из медицины: **норма** (отклонения нет) и **«тяжёлое»** (максимум). Тогда степень выраженности:

**sᵢ = (измерено − норма) / (тяжёлое − норма)**, обрезанная в диапазон [0 … 1]

| Параметр | норма (s=0) | тяжёлое (s=1) |
|---|---|---|
| ИАГ (апноэ) | 5 (дети 1) | 30 |
| ODI | 5 | 30 |
| SpO₂ min | 90 | 80 |
| Индекс храпа | 30 | 300 |
| Открывание рта | 35 мм | 20 мм |
| ЭМГ асимметрия | 15 % | 40 % |
| T-scan | 60 % | 80 % |
| EAT-10 | 3 | 15 |
| Саливация | 7 | 20 |

Теперь sᵢ — это **«на сколько процентов пути к тяжёлому»**. Пациент Б SpO₂ 76 → s = (90−76)/(90−80) = **1.0**; храп 192,6 → s = (192,6−30)/(300−30) = **0.60**. Каждое число имеет чёткий смысл.

### Слой 2. Вес нарушения — не выдуманный, а по уровню угрозы
Вес wᵢ — это **потолок вклада** (сколько максимум может добавить это нарушение), привязанный к рангу: жизнеугрожающее = 1.0, высокое = 0.7, среднее = 0.5, низкое = 0.3. Ранг — клиническое решение, но оно **явное и одно на всех**, а не «почему 0.9». Главное: реальный вклад = wᵢ × sᵢ, т.е. **зависит от цифры пациента**, а не фиксирован.

### Сборка индекса (0–100)
Не просто сумма (тогда три пустяка «перевесят» одно апноэ). Беру **«объединение»** (noisy-OR) — так одно тяжёлое жизнеугрожающее нарушение само по себе даёт высокий индекс, а мелкие накапливаются:

**ФИ = 100 · (1 − Π(1 − wᵢ·sᵢ))**

*Пример Пациент А:* ЭМГ 39,8 % (s≈1.0, w 0.6 → 0.60), T-scan 63,7 (s 0.19, w 0.5 → 0.09), логопед (0.4):
ФИ = 100·(1 − 0.40·0.91·0.60) = **≈ 78 / 100**.

(Евклидова формула — √Σ(wᵢsᵢ)² — тоже вариант, но она «размывает» одно тяжёлое нарушение среди нулей; для жизнеугрожающих состояний «объединение» честнее. Могу сделать и так.)

### Связка с ИА/ИНЧ
Морфологию тоже нормируем: **m = (ИА − 3)/(20 − 3)** → ИА 18,8 → m ≈ 0.93. Итог:

**Показатель к ДО = 100 · (0.6·m + 0.4·ФИ)** — морфология ведущая, функция усиливает. (коэффициент 0.6/0.4 настраивается).

## 2. Математические формулы для MOFI

Все работают с тяжестью sᵢ∈[0..1] и весами wᵢ:

| Формула | Суть | Когда хороша |
|---|---|---|
| **Взвешенная сумма / среднее** | Σwᵢsᵢ | просто, но тяжёлое «размывается» лёгкими |
| **Евклидова (RMS, p=2)** | √(Σwᵢsᵢ²/Σwᵢ) | подчёркивает крупные значения |
| **Степенное среднее (Hölder)** | (Σwᵢsᵢᵖ/Σwᵢ)^(1/p) | **одна «ручка» p**: p=1 среднее, p=2 евклид, p→∞ = максимум |
| **Объединение (noisy-OR)** ← сейчас | 1−Π(1−wᵢsᵢ) | «любое тяжёлое жизнеугрожающее → индекс высокий» |
| **Логистика (сигмоида)** | 1/(1+e^−k(x−x₀)) поверх суммы | даёт «S-кривую» и чёткий порог решения |
| **Расстояние Махаланобиса** | многомерное отклонение от нормы с учётом корреляций | статистически строго, **но нужна база данных** |
| **Логистическая регрессия** | веса подобраны по реальным исходам | «золотой стандарт», тоже **по базе** |

Мой совет: **оставить noisy-OR** (понятно, ограничено 0–1, «одно тяжёлое → высоко»), а как накопится база в облаке — перейти на **логистическую регрессию / Махаланобис** (тогда и веса, и пороги посчитает сама база — субъективности ноль). Если хочешь «одну ручку чувствительности» уже сейчас —可 добавить **степенное среднее с p** (ты крутишь p от 1 до 2 и видишь, как меняется баланс «сумма ↔ максимум»). Скажи, какой вариант нравится — внедрю.
